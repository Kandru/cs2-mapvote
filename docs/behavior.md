# Behavior

## Catalog

[`MapCatalog`](../src/MapVote/Maps/MapCatalog.cs) loads maps over localhost RCON (`127.0.0.1`, server port + `rcon_password`). Empty password → no load (logged once). Sources are controlled by `catalog.query_local_maps` (`maps *`, always local) and `catalog.query_mapgroup` (`print_mapgroup_sv`); both default to `true`. `print_mapgroup_sv` is parsed by [`MapGroupList`](../src/MapVote/Maps/MapGroupList.cs): a `Map group: workshop` collection lists workshop maps by bare name, while an admin mapgroup uses bare local names and `workshop/<id>/<name>` paths for workshop maps. When both switches are `false` no RCON query runs and the previous list stays. Each selected list is capped at `MaxMaps` (200); the end-match vote can be capped lower by `endmatch.max_maps`, while the browser uses the full grid pool. Keys in config use `map_` / `ws_` from [`MapOrigin`](../src/MapVote/Maps/MapEntry.cs). Both replies use one playability filter ([`MapNameFilter`](../src/MapVote/Maps/MapNameFilter.cs)): local paths, `workshop_preview_*`, `*_vanity`, `*_skybox`, `error`, `graphics_settings`, `lobby` and `lobby_mapveto` are skipped. The current map is normalized through the same rules, so a workshop path or numeric workshop id resolves to its workshop tile.

Refresh runs on intermission (not on plugin load, map start, or the win panel). The worker retries until the enabled replies look ready ([`MapListReadiness`](../src/MapVote/Maps/MapListReadiness.cs)) or the 1s budget elapses. A disabled source is not queried and does not block readiness. The path is chosen when that refresh settles, or at 2s if it has not. A later settle does not flip the path. A blank or banner-only body is not published over a previous good list. Worker thread → `Server.NextFrame` for the `maps` settings sync: first-seen timestamps are recorded and config edits are applied on every publish. Only a fully ready reply prunes entries for maps that disappeared. A request that arrives while the worker is busy is coalesced and started through `Server.NextFrame`; the RCON worker never reads ConVars or starts a refresh directly. A generation counter invalidates late callbacks and queued work across map changes.

## End-match vote

[`EventCsIntermission`](../src/MapVote/MapVote.cs) closes RTV and starts the path decision ([`MapVote.VoteFlow.cs`](../src/MapVote/MapVote.VoteFlow.cs), [`EndMatchFlow`](../src/MapVote/Voting/EndMatchFlow.cs)). The win panel is about 3s later and only opens our HUD. Map start writes the stretched engine timer. RTV does not arm or disable the Valve vote.

1. Intermission — catalog refresh, 1s budget. As soon as it settles, or at 2s at the latest, decide from the list already in hand.
2. Candidates — `mp_endmatch_votenextmap 0`, `mp_match_end_restart 0`, and the engine timer (`mp_endmatch_votenextleveltime` and `mp_match_restart_delay`) set to the vote length plus 4s so it expires after our `changelevel`. Blank `EndMatchMapGroupVoteOptions` and `EndMatchMapGroupVoteTypes` to `-1` now and once more next frame, then mark `m_pGameRules` changed so the client receives the empty list.
3. No candidates — `mp_endmatch_votenextmap 1` and `mp_match_end_restart 0`. Our HUD stays closed. The Valve panel is the only vote. Its option list is not cleared.
4. Win panel — custom path only. Blanks the native option list again and marks `m_pGameRules` changed so clients drop the maps. Optionally the menu length still follows `endmatch.vote_seconds`. Does not query RCON. If the win panel arrives before the 2s decision, the decision runs first with the current list. After the fixed 6s match-results hold, the Panorama HUD opens. Reveal is reserved at the end of the remaining window. `nextlevel` is set when the winner locks. `changelevel` (or `ds_workshop_changelevel`) runs one second before the vote length elapses, measured from the win panel — not from the stretched engine timer. A second change is ignored. Map end does not issue one. The same engine hold is also written on map start, before the next intermission reads it.

Master clock for the menu: win-panel epoch via [`VoteClock.ResolveCustom`](../src/MapVote/Voting/VoteClock.cs). Example with vote time 20 and reveal 5: menu at 6s, reveal at 14s, `changelevel` at 19s. Session state: [`VoteSession`](../src/MapVote/Voting/VoteSession.cs).

## RTV

[`MapVote.Commands.cs`](../src/MapVote/MapVote.Commands.cs): `css_rtv` / `rtv` (chat `!rtv`). Humans with a usable SteamID64 only; one vote per SteamID. Need `ceil(eligible_humans * ratio)`. On success: chat, then `rtv.success_command`. The native vote is left for intermission to decide. Blocked while an end-match phase is already running.

The first vote opens a window: `rtv.duration_seconds` (default 60; `0` = no limit) cancels and clears votes when it elapses; `rtv.announce_seconds` (default 15; `0` = off) posts the tally on whole remaining-time boundaries. A 60s window with a 15s interval announces at 45s, 30s and 15s left, never at 0. Later votes do not reset the deadline. [`OnTick`](../src/MapVote/MapVote.cs) drives expiry and reminders from one deadline; the window stops without an expiry line when RTV passes, the last voter leaves, intermission fires, the map starts, or the plugin unloads.

`EventCsIntermission` closes RTV (clears voters, clears the deadline/reminder schedule, rejects further `!rtv` with `rtv.ended`). It stays closed while our vote is on screen. It opens again on `OnMapStart`, or when the same map starts another match: `EventRoundAnnounceWarmup`, `EventRoundAnnounceMatchStart`, or `EventBeginNewMatch`. A finished native vote returns to idle at that point so the next intermission can decide again.

## Map browser

`css_maps` / `maps` / `css_nom` / `nom` / `css_nominate` / `nominate` (chat `!maps` / `!nom` / `!nominate`) open the same Panorama overlay in browse mode with [`VoteHud`](../src/MapVote/Huds/VoteHud.cs): type and Favorites chips, per-player sort chips (A-Z selected by default, newest, oldest, most positive rated, most negative rated), the current-map card with rating, up to 200 map cards starting in A-Z order, and the same live ranking as the end-match vote. Each card carries the server-wide like/dislike counts in a pill at the top-left; counts use the viewer's thousands separator (for example `1.000`). A thin bar along the bottom edge of every card image shows the like share (green over red, grey when unrated; mixed ratings never show fully green or red), in the vote too. Browse cards also show the date the map was added (`maps.*.added`, UTC day, format from `hud.added_format`; empty when unknown), and the title shows the total map count ("Maps · 152"). If every catalog map is hidden by `maps`, the browser shows its empty state and nominations are disabled for that list. With `nominations.enabled` (default `true`), map tiles and ranking rows are clickable and each human can nominate one map; clicking another map moves the nomination and clicking the same map does nothing. The ranking and the vote badges on the cards show which maps already have nominations, updating for every open browser. A player can change their pick once per second; a faster click plays a blocked sound and changes nothing. Without nominations, browse has no vote target and tiles are not clickable. The Close button closes the overlay for that player.

Nominated maps are guaranteed candidates in the end-match vote, subject to `maps`, `endmatch.exclude_current_map`, and `endmatch.max_maps`. If there are more nominations than slots, the most-nominated maps (then earliest nominations) win. When the final vote opens, each nominator's vote is already cast for their nominated map and counts in the Leading ranking; the player can still change it, subject to the same one-second limit. Nominations reset on map end and map start, and a disconnecting player's nomination is removed.

The command triggers a short catalog refresh when the list is still empty after plugin load, then opens for everyone who was waiting. Intermission (`EventCsIntermission`) and map end close the browser and reject `!maps` until `OnMapStart`, warmup, match start, or a new match. An active end-match vote also rejects it (`maps.busy`).

## HUD

- Layout path: `panorama/layout/custom_game/mapvote/vote_{PanoramaVersion}.vxml_c` (`PanoramaVersion` from [`Version.cs`](../src/MapVote/Version.cs)).
- Styles: `hud_v3` (UI) + `maps_v1` (generated map images) under workshop content; sources in `workshop/content/`. The layout version comes from [`Version.cs`](../src/MapVote/Version.cs); `tools/generate_vote_xml.py` generates its XML and CSS ladders, and its docstring is the id contract that [`VoteIds`](../src/MapVote/Huds/VoteIds.cs) mirrors.
- Paint / clicks: [`VoteHud`](../src/MapVote/Huds/VoteHud.cs) + [`CustomHud`](../src/MapVote/Utils/CustomHud.cs) (`CheckTransmit`, dialog vars, classes, input capture). Fixed slot pools - see [PANORAMA_RULESET](../stuff/PANORAMA_RULESET.md). The XML pool is 200 grid cards + 6 ranking rows. Every human gets a private `custom_hud_layout` entity on connect full; it is transmitted only to its owner and removed on disconnect, map end and plugin unload. All values are written on that private entity, so the diff caches work per viewer and a sort/filter never touches anyone else's overlay. Type and favorites filters are per player; sort chips order that player's grid without changing the map count and are available in both the end-match vote and the browser. All map data (names, origins, first-seen timestamps, vote sessions and server-wide rating counts) is shared; a snapshot built once per bind keeps it identical for every viewer, and only sort order, filter selection and favorites live per player. `display.order` picks the base order (`shuffle`, assigned once per match, or `alphabetical`); the Leading ranking is global and shows the top 6 by vote count.
- The current-map card shows the current map with its favorite button, the question "How was this map?" and two labelled buttons, Like and Dislike, with server-wide counters. Each player's own rating is highlighted and can be changed. Rating and map voting are not possible during the reveal; the Hide/Show control stays available so a viewer can collapse the result.
- The grid is one `flow-children: right-wrap` scroll panel of landscape cards, so the column count follows the viewport width; only the grid scrolls. `right-wrap` is the documented Panorama deviation and must be verified in game.
- Tiles: the vote badge is shown only when a map has votes, `is-self` marks the local vote and the favorite star sits top-right. The Leading ranking lists up to 6 maps with vote count and share bar, marks your own vote, and clicking a row votes for that map. It is live in browse mode as well. A player can change their vote at most once per second ([`VoteSession.ChangeCooldown`](../src/MapVote/Voting/VoteSession.cs)); a faster click plays the blocked sound and is otherwise ignored.
- Reveal: the grid is dimmed and a centered "Next map" card shows the winner with its vote count, or "random pick - no votes".
- Map tile classes: `mv-map-map_{name}` / `mv-map-ws_{name}` / `mv-map-default` ([images.md](images.md)).
- The browser preview under `workshop/preview/` is regenerated by `make panorama`. `sync_preview.py` reads the type/sort defaults from `ConfigDefaults.cs`, the nominations default from `PluginConfig.cs`, and the German strings from `lang/de.json`, so the mock cannot drift into a separate configuration.

## Lifecycle and reset

State is owned by two symmetric entry points in [`MapVote.cs`](../src/MapVote/MapVote.cs):

- `InitializeRuntimeState` runs on `Load` (including hot reload) and `OnMapStart`. It returns every per-map runtime value to its startup default: vote flow epoch and session, pending candidates/winner/origins, timing fields, catalog generation, RTV voters/deadline/flags, deferred HUD-open tokens, pending `!maps` waiters, nominations and the simple-map-browser flags. It then resets the HUD view, initializes `CustomHud`/`HudMenu`, and resets `MapOrder`. The cached original server vote length is retained across maps. On a normal start, the live-server attach — queueing the per-player layout entities and arming the engine hold — runs from `OnMapStart`, once the engine globals exist. A reload or late load attaches from `OnAllPluginsLoaded` when CSS reports `hotReload`, because `OnMapStart` will not fire mid-map. Map start additionally loads persistence.
- `ShutdownRuntimeState` runs on `OnMapEnd` and `Unload`. It bumps the flow timer epoch so every delayed callback becomes a no-op, closes the vote and browser, clears all pending/cached state, invalidates the catalog generation, resets the HUD view and shuts down `CustomHud`/`HudMenu`. Map end and unload therefore leave the same inert state; unload additionally removes listeners and event handlers. `Load` does not depend on a previous `Unload`, and `OnMapStart` does not depend on `OnMapEnd`.

Deferred HUD opens use [`SlotActionTokens`](../src/MapVote/Runtime/SlotActionTokens.cs): each slot has one current generation, a newer open supersedes an older one, and clearing the slot/map invalidates anything still waiting on a timer. This is also why a first or repeated `!maps` can never hit a missing dictionary key.

Votes, RTV votes, nominations, pending open waiters and player archives are keyed by SteamID64; HUD layouts and menu sessions are owner-bound and verified against it. An engine slot is only a short-lived handle for the player controller and its private layout entity; it is never used as the player identity. Disconnect cleanup resolves the SteamID first, checks that the slot still has that owner, and only then kills the layout/menu and drops queued HUD state. Vote/nomination/RTV/archive entries are removed by SteamID; the archive is saved on disconnect. A reused slot can therefore never be cleaned up or receive the previous owner's HUD.

## Localization

Chat + HUD strings: [`lang/en.json`](../src/MapVote/lang/en.json), [`lang/de.json`](../src/MapVote/lang/de.json). Filter/sort chip labels use `filter.{id}` / `sort.{id}` matching config ids. Type chips append the matching map count as `Label (n)` - for example `All (95)` - and the Favorites chip counts only the viewer's favorites that are in the currently displayed map list, including `Favorites (0)`. Favorites for maps that left the rotation stay saved and reappear if the map returns. Every HUD text is written on the viewer's private layout entity, so each player sees it in their own language.
